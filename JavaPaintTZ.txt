1. Общие сведения
Название проекта: JavaPaint
Тип продукта: растровый графический редактор
Назначение: программное обеспечение для создания и редактирования растровых изображений с функциональностью, аналогичной Microsoft Paint, включая современные возможности: слои, прозрачность, историю действий и ИИ-инструменты.

Целевые платформы: Windows, Linux, macOS
Рекомендуемый стек: Java (последняя LTS-версия), JavaFX для интерфейса, Maven или Gradle для сборки, JUnit для тестирования.
Пользователи: новички, студенты, пользователи, которым нужен простой редактор без сложного интерфейса профессиональных программ.

Границы проекта:

Входит: рисование, фигуры, текст, выделение, трансформации, слои, работа с файлами, история, ИИ-функции.

Не входит: векторная графика профессионального уровня, 3D, анимация, видеомонтаж, работа со звуком.

2. Цели и задачи
Цель: создать полнофункциональный растровый редактор, повторяющий и расширяющий возможности Microsoft Paint.

Задачи:

Реализовать базовый набор инструментов рисования.

Обеспечить работу с фигурами, текстом и выделением.

Добавить поддержку слоёв, прозрачности и истории действий.

Реализовать открытие и сохранение файлов популярных форматов и собственного формата проекта.

Внедрить ИИ-функции (по желанию заказчика).

Обеспечить кроссплатформенность, производительность и удобство интерфейса.

3. Функциональные требования
3.1. Инструменты рисования
Карандаш: тонкие линии с настраиваемой толщиной.

Кисть: плавные линии нескольких стилей (масляная, маркер, аэрограф), с настройкой размера и непрозрачности.

Ластик: удаление пикселей, регулируемая прозрачность и размер.

Распылитель: имитация распыления краски.

Заливка: закрашивание замкнутых областей с настраиваемым допуском.

Пипетка: выбор цвета с изображения или палитры.

3.2. Фигуры
Линия, кривая, прямоугольник, скруглённый прямоугольник, эллипс, треугольник, ромб, пятиугольник, шестиугольник, многоугольник.

Настройка контура: толщина, цвет, стиль.

Настройка заливки: цвет, отсутствие, градиент.

3.3. Выделение
Прямоугольное, произвольной формы, «умное» (на основе ИИ).

Операции: перемещение, копирование, вырезание, вставка, удаление, инверсия, обрезка по выделению.

Сохранение выделенной области в отдельный файл.

3.4. Текст
Ввод текста, выбор шрифта, размера, начертания, цвета, выравнивания.

Вставка текста как редактируемого объекта до подтверждения и как растрового слоя после.

3.5. Трансформации
Изменение размера, наклон, поворот, отражение, инверсия цветов.

Изменение размеров холста, обрезка.

Включение сетки для точного позиционирования.

3.6. Слои и прозрачность
Создание, удаление, переименование, изменение порядка.

Управление видимостью, непрозрачностью, режимами наложения.

Поддержка прозрачности, отображение шахматной доской.

Сохранение проектов со слоями в собственном формате.

3.7. История действий
Отмена и повтор не менее 50 шагов.

Каждое действие — отдельная команда, которую можно отменить или повторить.

3.8. Работа с цветом
Основной и фоновый цвет.

Стандартная палитра, пользовательские цвета, пипетка.

3.9. Работа с файлами
Открытие: PNG, JPEG, BMP, GIF, TIFF, WMF, EMF.

Сохранение: PNG, JPEG, BMP, GIF, TIFF, собственный формат проекта.

Экспорт выделенной области.

Печать изображения.

3.10. ИИ-функции (опциональный модуль)
Создание изображения по текстовому описанию.

Создание изображения по наброску и описанию.

Генеративная заливка: удаление и замена объектов с дорисовкой ИИ.

Создание страниц-раскрасок.

Создание стикеров.

Все ИИ-операции выполняются асинхронно, с индикатором прогресса и возможностью отмены.

API-ключи хранятся в защищённом виде.

3.11. Интерфейс
Лента или панель инструментов.

Панель слоёв.

Палитра цветов.

Строка состояния.

Горячие клавиши для основных действий.

Тёмная и светлая темы.

Локализация (русский, английский).

4. Нефункциональные требования
Производительность: отклик при рисовании не более 50 мс, частота отрисовки не ниже 60 кадров в секунду, поддержка холстов до 10 000 × 10 000 пикселей.

Память: тайловая отрисовка, ленивое вычисление композиции слоёв, освобождение неиспользуемых буферов.

Кроссплатформенность: одинаковый функционал на Windows, Linux, macOS.

Надёжность: автосохранение, восстановление после сбоя, защита от потери данных.

Безопасность: шифрование API-ключей, ограничение сетевой активности, отсутствие телеметрии без согласия пользователя.

Тестируемость: модульные тесты для модели и логики, UI-тесты для интерфейса, ручное тестирование.

Расширяемость: возможность добавления новых инструментов и эффектов без переписывания ядра.

5. Архитектура (словесное описание)
Приложение строится по принципу разделения ответственности. Выделяются следующие слои:

Слой представления — окна, панели, холст, панель слоёв, палитра, диалоги.

Слой контроллеров — обработка действий пользователя, связь интерфейса с моделью.

Слой инструментов — каждый инструмент реализуется отдельно и следует единому контракту.

Слой модели — документ, слои, пиксельные буферы, выделение, палитра.

Слой команд — каждое действие оформляется как команда для поддержки отмены и повтора.

Слой рендеринга — композиция слоёв и вывод изображения на холст.

Слой ввода-вывода — чтение и запись файлов, собственный формат проекта.

Слой ИИ-сервисов — асинхронные вызовы внешних или локальных моделей.

Слой утилит — работа с цветом, геометрией, математикой, конфигурацией.

Поток данных: пользователь → контроллер → инструмент → команда → модель → рендеринг → холст.

6. Модель данных (словесное описание)
Пиксельный буфер — прямоугольная сетка пикселей с координатами и цветом в формате ARGB.

Слой — имя, видимость, непрозрачность, режим наложения, пиксельный буфер.

Документ — размеры, список слоёв, активный слой, текущее выделение, менеджер истории.

Выделение — геометрическая форма и маска, определяющая, какие пиксели входят в область.

Палитра — основной и фоновый цвет, набор пользовательских цветов.

Команда — объект с методами выполнения и отмены, описывающий одно действие.

Менеджер истории — хранит стеки отмены и повтора с ограничением по количеству.

7. Ключевые контракты (без кода)
Инструмент должен уметь: реагировать на нажатие, перетаскивание и отпускание мыши, обрабатывать нажатия клавиш, рисовать предпросмотр, сообщать своё имя и параметры.

Команда должна уметь: выполниться и отмениться, возвращать своё имя.

Менеджер истории должен уметь: выполнять команду, отменять, повторять, очищать историю, ограничивать глубину.

Композитор должен уметь: собрать итоговое изображение из слоёв с учётом видимости, непрозрачности и режима наложения.

Сервис ИИ должен уметь: асинхронно генерировать изображение по описанию, выполнять генеративную заливку, создавать раскраски и стикеры, поддерживать отмену.

8. Формат проекта (словесное описание)
Собственный формат проекта — это архив, содержащий:

файл-манифест с метаданными: версия, размеры холста, активный слой, список слоёв с их параметрами;

отдельные изображения для каждого слоя в формате PNG с сохранением прозрачности.

Это позволяет сохранять слои, прозрачность и порядок наложения, а также легко восстанавливать проект.

9. Интеграция ИИ (словесное описание)
ИИ-функции реализуются как отдельный модуль, обращающийся к внешним или локальным сервисам. Все запросы асинхронные, с индикацией прогресса. Ключи доступа хранятся в конфигурации или переменных окружения и не попадают в исходный код. При недоступности сервиса функции отключаются без влияния на остальную работу редактора.
